Building my own portfolio website has been useful for more than displaying projects.

It has given me a place to practice the same SEO, analytics and website-measurement principles I use when working on business websites.

## Owning the implementation changes how I think

When I control the website, I have to think beyond content.

I need to consider:

- Site structure
- Internal links
- Metadata
- Canonical URLs
- Mobile experience
- Page speed
- Analytics
- Search Console
- Structured data
- Sitemaps
- Indexing

That makes the portfolio itself a practical learning environment.

## Moving to a custom domain

I moved the portfolio to `waiyanaung.me` so the website could have a clearer long-term identity.

A domain migration also taught me that changing a URL is not only a branding decision.

Search-related considerations include updating canonical URLs, Open Graph URLs, structured data references, the sitemap and Search Console configuration.

The important lesson is consistency: all signals should point toward the preferred domain.

## Search Console is part of the build

I do not see Google Search Console as something to install after SEO is “finished.”

It is part of the feedback loop.

After publishing or changing site structure, Search Console helps me understand indexing, search visibility and how Google sees important URLs.

SEO implementation without monitoring leaves too many questions unanswered.

## GA4 tells me how the portfolio is actually used

GA4 gives me a different perspective.

Instead of only asking whether the site appears in search, I can evaluate acquisition channels, engagement and page behavior.

This is especially useful for a portfolio because visitors may arrive from direct links, social platforms, search engines or other sources.

## Structured data needs to describe reality

I added structured data to help search engines understand the person and page entities on the website.

The lesson I keep in mind is that schema should describe what is actually present — not create claims that the visible page cannot support.

For a personal portfolio, clear Person and page-level information is more useful than adding unnecessary schema types.

## Performance is part of user experience

I also tested the site with performance tools and optimized assets such as the profile image.

This reminded me that technical SEO is connected to design decisions.

Large images, third-party assets and unnecessary scripts can affect loading performance even when the page looks visually simple.

## A portfolio should demonstrate process

A digital marketing portfolio becomes stronger when it shows how I think, not only what I produced.

That is why I am expanding the site with articles on:

- SEO
- Local SEO
- GA4
- Google Search Console
- Google Business Profile
- Measurement
- Meta Ads

The blog is not separate from the portfolio. It is another way to demonstrate practical knowledge and document what I learn.

## My biggest takeaway

Building a portfolio website has helped me connect several skills that are often treated separately:

**SEO + analytics + web implementation + content + reporting.**

That combination is increasingly important to the direction I want to develop professionally.
